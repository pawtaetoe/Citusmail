# mail_trust

Local checks that warn about suspicious mail. Pure Dart. Everything runs on
the device: no lookups, no reputation service, nothing sent anywhere. The
checks only report; mail is never moved or deleted because of them.

`TrustChecker.check(view, context)` returns a `TrustReport`: a level
(ok, caution, danger), reasons in plain words, and verdicts for single
links and attachments.

| Check | Level |
| --- | --- |
| Your own server's DMARC result is `fail` | danger (caution for mailing lists, and for forwarded mail whose ARC chain your own server found valid, `arc=pass`) |
| No DMARC, but SPF fails for the sender's domain | caution |
| Display name claims a brand (PayPal, Microsoft...) the address doesn't belong to | danger (caution for ordinary words such as "Chase") |
| Sender domain imitates a brand (`paypa1.example`, `paypal-login.example`) or your own domain (`t0mmykung.cc`) | danger |
| Domain mixes alphabets (`аpple` with a Cyrillic "а") | danger |
| Display name shows a different email address | caution (danger if it is a brand's) |
| Link text shows a brand's address but goes elsewhere; `user@host` tricks; lookalike link domains | danger |
| Link text shows another address (often a newsletter's tracking redirect) or goes to a bare IP | flagged on the link only |
| Attachment is a program, a program posing as a document (`invoice.pdf.exe`) | danger |
| Attachment is a disk image, a macro document or a web page | caution |
| The subject names the reader's own organisation (its initials or name spell a label of an address the mail went to, e.g. "Singapore Institute of Technology" for `sit.singaporetech.edu.sg`), but the sender is outside it | caution; danger with a hidden recipient list or a form link |
| The message writes in the name of a well-known company (subject, "in partnership with" / "on behalf of", or a signature line naming a team or office) that the sender's domain doesn't belong to | caution; danger with a hidden recipient list or a form link |
| Hidden recipient list (`To: undisclosed-recipients:;`, or only Bcc) | caution |
| A link opens a free form service (Google Forms, Microsoft Forms, Typeform...) | caution, also on the link |

The last four catch scams from real, verified addresses (often a hijacked
account), which pass every sender check.

**Which verification results count.** Anyone can write an
`Authentication-Results` header. Only results from the user's own server
are used: its name is learned from the topmost header of recent inbox mail
(the same name on at least 5 messages and 60% of them), and only the run
of headers at the top with that name is read. A result written further
down, or under another name, is ignored. Until the name is known,
verification checks are skipped.

**Domains.** `Domains.registrable` uses the Public Suffix List
(`lib/src/generated/public_suffixes.g.dart`, generated by
`dart run repo_tools:generate_public_suffixes` from the checksummed copy in
`tool/third_party/publicsuffix/`). `Punycode` decodes `xn--` labels;
`Lookalikes` maps Cyrillic and Greek letters, digits and `rn` to the Latin
letters they imitate.
